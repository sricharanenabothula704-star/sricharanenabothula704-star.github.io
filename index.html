In plain language

Bug hunting is 90% tedious work.
HYDRA automates the tedious 90%.

Companies pay hackers (bug bounties) to find security flaws in their apps. Finding one flaw means scanning thousands of pages, reading mountains of code, and testing the same things over and over. HYDRA is a team of AI agents that does that grind for you — then hands you a verified lead with proof attached.

1 What's an "agent"?

A software worker with a job description. Each HYDRA agent is a specialist — one scans networks, one double-checks findings, one writes the final report. They read files, run commands, and talk to each other so you don't have to babysit ten terminal windows.

2 What does it actually do?

For guarded workflows, give it a target you're authorized to test. Depending on enabled tools and configuration, HYDRA can map assets, fingerprint technologies, run checks, and prepare candidate findings for review. Verify evidence yourself before reporting.

3 Why verification matters

Bounty platforms reject unsupported reports. HYDRA's Verifier is intended to challenge leads with repeat checks and evidence review, but its checks are heuristic—not a guarantee. Treat results as candidates and reproduce them yourself before submitting.

Getting started

From zero to first scoped run

Linux, macOS, or WSL. Prefer an AI coding agent? Open the copy/paste setup prompt; it tells the agent to explain changes, back up config, and ask before installing.

Install

Clone the repo and run bash setup.sh --handle YOU --email you@example.com. Setup backs up an existing config and asks before installing OpenCode or replacing that config.

Pick a model provider

The default config uses OpenRouter. Set OPENROUTER_API_KEY in your shell before launching OpenCode. Other providers need a matching provider/model config; the model helper shows supported credentials.

Confirm your authorization

Only test assets you own or have written authorization to assess. Add exact authorized domains to ~/.config/opencode/SCOPE_ALLOWLIST.txt; the CLI and loop runner deny targets outside it.

Hunt

Add authorized domains to the scope allowlist, launch opencode, and use guarded CLI or loop commands for scope checks. Direct agent commands and standalone scripts need your own scope review. Findings are local by default, but configured AI providers receive prompts and optional integrations may transmit findings.

Verify, then report

Feed leads to /verify. Survivors go to /report — out comes a submission-ready writeup with reproducible PoCs. Submit, collect, repeat.

Evidence and limitations

What is checked—and what is not

A clear distinction between automated checks, security boundaries, and work still needed.

Automated checks

CI runs Python compilation, index consistency, unit tests, scope-policy tests, frontmatter checks, and a secret-pattern scan. These checks establish basic integrity; they do not prove every skill or security claim is correct.

Scope boundary

The CLI and loop runner gate their supported commands against a local allowlist. Prompt instructions are not a substitute for enforcement: standalone scripts may bypass that gate, so inspect each script before use.

Known limitations

There is no benchmark suite establishing precision or recall yet. Oracle checks are heuristics and may miss bugs or produce false positives. Human review and reproduction are required before any report or action.

Questions people actually ask

FAQ

Is this legal to use?
Use it only on systems you own or have written authorization to test. The CLI and loop runner enforce the local allowlist for their guarded commands, and agent instructions require scope review. Standalone helper scripts may not enforce the allowlist; inspect them and confirm scope before running any script or sending traffic.
Will it find bugs fully automatically while I sleep?
No — and be suspicious of anything claiming otherwise. HYDRA automates recon, pattern-matching, verification drudgery and report writing. Judgment — choosing targets, reading business logic, deciding what's worth pursuing — stays with you. Think of it as a very fast junior team you direct, not an autonomous money printer.
Do I need paid API keys?
You need an AI model provider for model-backed workflows. Some providers offer free tiers; a local Ollama setup can keep model prompts on your machine. Cloud providers receive the prompts sent to them, and configured tools may contact their targets or other services. Review provider terms, privacy settings, and scripts before use.
What makes this different from just using ChatGPT?
ChatGPT gives advice; HYDRA executes. It runs real scanners against real targets, keeps per-agent memory across sessions, enforces verification discipline, and produces reports in exact platform format. It's a workflow with guards, not a chat window.
Can it break my computer or leak my data?
Findings are stored locally by default, but this is not a guarantee that all data stays local. The optional coordination server binds to 0.0.0.0:5000 without authentication and serves submitted findings over HTTP; do not run it as shipped. The config also grants the build agent shell and edit permissions. Review scripts, permissions, and provider data handling before use.
What if an agent gets stuck or hallucinates?
The prompts include recovery and evidence-review guidance, but agents can still get stuck or make mistakes. Treat every result as a candidate; independently reproduce it, inspect raw evidence, and review reports before submission.
